## Phase III recap

- `src/core/layout/{interpreter,fonts,standard14,words}.rs` interpret the
  content stream (q/Q, cm, BT/ET, Tm/Td/TD/T*/TL/Tf/Tc/Tw/Tz/Ts, Tj/TJ/'/", Do),
  with form XObjects recursed through `/Matrix × CTM` and images reported as
  `PlacedImage` from the unit square under the CTM.
- Glyph widths come from `/Widths`, Type0 `/W` + `/DW`, Type3 `/FontMatrix`, or
  the Standard 14 AFM tables; subset prefixes are stripped.
- Bold is decided from the font name, the ForceBold flag or `/FontWeight >= 600`
  only. `StemV` was dropped: Microsoft Print To PDF writes 833 for regular
  Times New Roman, which flagged every word bold on two invoices.
- Words split on space glyphs, `Tw` gaps, `TJ` adjustments ≤ −200/1000 em,
  baseline changes > 0.5 em, gaps > 0.25 em and backtracks > 0.5 em. Lines are
  clustered by baseline within 0.5 × the median word height, ordered
  top-to-bottom then left-to-right.
- API: `layoutPerPage[Async]`, `PdfDown.layout[Async]`; OCR package adds
  `extractLayoutWithOcrPerPage[Async]` and `PdfDown.layoutWithOcr[Async]`.
  `TextSource` (`Native | Ocr | Rendered`) is unconditional now.
- Fixture `__test__/fixtures/layout/layout-sample.pdf` is generated by
  `cargo run --example gen_fixtures` (then `git checkout -- __test__/fixtures/forms/`
  because the RC4 fixture is not bit-stable).

Reading order is correct on all 19 native-text invoices in the private corpus,
with zero warnings.

## The scanned invoice (16-page copier scan)

A Ricoh copier scan in the private corpus: every page is one 1-bit
`CCITTFaxDecode` image, Group 3 1-D (`/DecodeParms` without `/K`), 2480×3508
at 300 dpi, zero native text. Pages 4–8 are landscape sheets fed through in
portrait, so their text runs vertically.

Two gaps it exposed, both fixed in `74278bc`:

1. **No CCITT decoder.** lopdf and the `image` crate both skip CCITT, so tier 2
   found nothing and every page fell to the PDFium render tier (76 s), which is
   optional. Now `hayro-ccitt` decodes Group 3 and Group 4 in pure Rust,
   honouring `/K`, `/Columns`, `/Rows`, `/BlackIs1`, `/EncodedByteAlign`,
   `/EndOfLine`, `/EndOfBlock` and `/Decode [1 0]`. Truncated streams are
   padded white. Applies to image extraction and OCR tier 2 alike.
2. **Rotated pages OCR'd as punctuation** at 0.36–0.41 mean confidence. Both
   OCR paths now retry at 90°, 270° and 180° when the upright pass scores under
   55 and produced text, keeping the best. `PageLayout.contentRotation` reports
   the clockwise turn; words, `width` and `height` are in the upright frame and
   a warning names the image.

Result: all 16 pages come through tier 2 as `Ocr`. Upright pages score
0.84–0.92; the rotated pages are detected at 90° and score 0.87–0.92, with the
dense repair form at 0.64 and the handwritten work order at 0.49.

A hand-coded 8×2 Group 4 fixture (`__test__/fixtures/ccitt-g4-tiny.pdf`) and
five Rust unit tests cover the decoder; `ocr/__test__/private-corpus.spec.ts`
OCRs only the scanned documents and writes `report-ocr.json` into the
gitignored private dir.

## Finding: OCR is 10× slower than it should be (OpenMP oversubscription)

The `tesseract` CLI does a full 300-dpi page in about 1 s; the library was
taking nearly 8 s per page on the same document. Ubuntu's libtesseract spawns
one OpenMP thread per core inside every recognise call, so four rayon workers ×
eight OpenMP threads thrash an eight-core box.

| Run (same document, identical results) | Total   | Per page |
| -------------------------------------- | ------- | -------- |
| 4 workers, default OpenMP              | 124.6 s | 7.79 s   |
| 4 workers, `OMP_THREAD_LIMIT=1`        | 10.2 s  | 0.64 s   |
| 8 workers, `OMP_THREAD_LIMIT=1`        | 10.1 s  | 0.63 s   |
| 1 worker, `OMP_THREAD_LIMIT=1`         | 26.1 s  | 1.63 s   |

**Not fixed yet.** The fix belongs in the package, not in user environments.
Candidates, in order of preference:

1. Set `OMP_THREAD_LIMIT=1` (or `OMP_NUM_THREADS=1`) in the JS loader before
   the `.node` is required — libgomp reads the environment in its constructor
   when the shared object loads. Needs a check that the generated `index.js`
   can carry it (napi-rs regenerates the loader; a wrapper entry may be needed).
2. `std::env::set_var` from Rust is too late if libgomp is already loaded; a
   tiny FFI call to `omp_set_num_threads(1)` at Tesseract init is the fallback.

Parallelism should come from `maxThreads` (rayon), not from OpenMP inside each
page.

## Finding: orientation can be detected before OCR (Tesseract OSD)

Tesseract's orientation and script detector is exposed by tesseract-rs 0.4 as
`TesseractAPI::detect_os() -> (orient_deg, orient_conf, script, script_conf)`.
It needs `osd.traineddata` (installed on this machine under
`/usr/share/tesseract-ocr/5/tessdata`; a separate apt package on some systems).

Measured with `tesseract <page>.png - --psm 0` on nine pages of the scan:

| Pages                  | OSD       | Confidence | Time        |
| ---------------------- | --------- | ---------- | ----------- |
| 1, 3, 9, 16 (upright)  | rotate 0  | 3.9–13.8   | 0.55–1.27 s |
| 4 (handwritten)        | rotate 90 | 11.0       | 1.18 s      |
| 5, 6, 7, 8 (landscape) | rotate 90 | 6.0–12.2   | 0.74–1.08 s |

Nine for nine, including the handwritten page where OCR confidence alone was
marginal. Gotcha: the API returns the text's _current_ orientation; the
clockwise correction is `(360 - orient_deg) % 360`. The CLI prints
"Orientation in degrees: 270 / Rotate: 90" for our 90° pages.

Recommended plan (not started):

1. Fix the OpenMP thrash first — it also shrinks the existing retry loop from
   ~30 s to ~3 s per rotated page.
2. Add OSD as a pre-pass, only on pages that will be OCR'd. Trust it above a
   confidence of roughly 3 and seed the rotation from it. Keep the confidence
   retry as the safety net for low OSD confidence, missing `osd.traineddata`,
   and pages OSD rejects for too few characters.
3. Per-document prior: try the previous page's rotation first. Copier batches
   almost always share orientation across consecutive pages.

Projection-profile heuristics (row vs column ink variance) would be cheaper
still but cannot tell 0° from 180° or 90° from 270°; at ~1 s per page OSD
already costs less than one OCR retry, so the heuristic is not worth building.

## Conventions worth remembering

- Private invoices live in `ocr/__test__/fixtures/private/` (gitignored). Tests
  may read them locally; no result, field value or page text from them goes in
  the repo. Both private-corpus specs skip when the dir is absent.
- Never run install commands; hand them to the user.
- oxfmt style: `trailingComma: "none"`, `semi: true`, double quotes. No type
  assertions except `as const`, no `any`, prefer `satisfies`; `UTR` for
  discriminated unions; `true satisfies IsExact<...>` for type tests.
- `index.d.ts` / `ocr/index.d.ts` are generated; utility types go in
  `types/dts-header.ts`. `Cargo.lock` is gitignored here.
- CI runs only on pushes to `main`.
