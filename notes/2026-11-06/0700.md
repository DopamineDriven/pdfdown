# 2026-11-06 07:00 — Phase IV slice 1: header fields from pages (design)

Status: design for the first slice of phase IV, the one that turns `PageLayout` pages into
invoice fields. It argues from `notes/2026-11-01.md` §7.3 (the module plan) and
`notes/2026-11-03/1037.md` §6 (phase IV revised) and changes neither; where this note is
narrower than those, the rest is slice 2 and later. Private corpus values never appear here.

## 1. Intent

`invoice()` returns `source: "None"` for every document without embedded XML, which is the whole
private corpus. This slice makes it return the header fields a reasonable person reads off the
first page, from the same `PageLayout` pages for a native PDF, an OCR'd scan and a workbook, with
a span and a confidence on every field, so the eval harness can print a number per cluster.

## 2. Goals, non-goals, anti-goals

Goals:

- `invoiceId`, `invoiceDate`, `dueDate`, `purchaseOrder`, `vendorName` (+ `vendorAddress`),
  `customerName` (+ `customerAddress`), `currencyCode`, `subTotal`, `totalTax`, `invoiceTotal`,
  `amountDue`, `workOrder`, and `aircraft[]` registrations and serials, each with `text`, `span`
  and `confidence`; `documentType` Invoice or CreditNote; `confidence` for the document;
  `source` naming the tier the pages came from (Native, Ocr, Rendered, Mixed).
- One engine for PDF pages and spreadsheet pages. Nothing in it knows a vendor or a template
  (`invoice-architecture-decisions`); the lexicon is a reviewed English table in the repo.
- Measurable on day one: the public fixtures pin exact values; `yarn invoice:eval` scores the
  private corpus unchanged once expected files exist.

Non-goals (slice 2 and later): line items and tables, multi-page continuation beyond the first
invoice page, page roles and bundle segmentation, `parties[]`, tax detail rows, payment details,
address-country priors for currency and date order, non-English lexicons, confidence
calibration against references.

Anti-goals: a value with no span; a number parsed under the wrong separator convention
silently; any per-vendor branch; any corpus value in a tracked file.

## 3. Shape of the result (unchanged types, three additions)

`InvoiceResult` and `InvoiceFields` stand as in `src/types/invoice.rs`. Additions, all additive:

- `InvoiceSource` gains `"Spreadsheet"`, as `notes/2026-11-05/0338.md` §3 already decided for
  the day extraction landed; a workbook's result reports it.
- `InvoiceResult.currencySource?: "Page" | "Content" | "Option" | "Unknown"` (1037 §6.8). This
  slice emits `Page`, `Option` or `Unknown`; `Content` arrives with the address priors.
- `InvoiceResult.creditSignals: string[]`: the evidence behind `documentType: "CreditNote"`
  (label hits, negative totals), empty otherwise.
- A standalone `invoiceFromLayout(pages: PageLayout[], opts?: InvoiceOptions)` with its async
  twin, in both packages: the engine on pages from anywhere, a consumer's `layoutWithOcr` call
  included. `invoice()` on the class and `extractInvoice` call it after their own layout.

## 4. How a document flows

1. Pages. A PDF: embedded XML first when `preferEmbeddedXml` (unchanged). Else native pages
   from `extract_layout` for every page; in the OCR build the cascade (`extract_layout_with_ocr`)
   with default options runs **on the first and the last page only**, the two pages this slice
   reads, so a 111-page scan does not cost a 111-page OCR inside `invoice()`; the cascade gains
   a page filter for that and `layoutWithOcr()` keeps reading every page. A workbook: `project()`
   pages. **Call:** the OCR build runs the cascade inside `invoice()`; the base build is native
   only and warns when the first page has no words. The async twin is the entry point to prefer;
   the sync one blocks for the OCR of two pages at most.
2. Priors, in one pass over page 1 (1037 §6.8 tiers 1, 3 and 4 only in this slice):
   currency from an ISO 4217 code near an amount or in a `Currency:` label, else an unambiguous
   glyph (`€`, `£`, `CHF`, `C$`), else `opts.currency`, else none; `$` alone is a glyph, never a
   code. Date order from any day greater than 12 on the page, else `opts.dateOrder`, else MDY.
   Decimal separator from a token of the shape `1.234,56` or `1,234.56`, else `opts`, else `.`.
3. Anchors (2026-11-01 §7.3 `anchors.rs`): for each lexicon hit, candidates are the remainder of
   the same line right of the label (after `:`), the nearest line below within 1.5 em of the
   label's x0, and the nearest line to the right on the same baseline. Each candidate scores
   `0.5·label + 0.3·validator + 0.2·geometry`, times the mean OCR word confidence of its span
   when the words are OCR words. Ties favour same-line-right, then below.
4. Validators: `dates.rs` (ISO, `MM/DD/YYYY`, `DD/MM/YYYY`, `DD.MM.YYYY`, `YYYY/MM/DD`,
   `Nov 1, 2026`, `1 Nov 2026`, `November 1st, 2026`, `01-Nov-26`, `27MAR2026`), `amounts.rs`
   (`$1,234.56`, `1.234,56 €`, `EUR 1 234,56`, `(123.45)`, `-123.45`, `123.45-`, codes and
   glyphs), `identifiers.rs` (invoice id 3–30 chars with a digit, PO, work order, registration
   shapes such as N-numbers and `C-XXXX`, serial shapes), each returning the normalised value.
5. Parties (`parties.rs`): vendor is the largest-font line in the top 25% of page 1 that is not
   a label, a date, an amount or a **document title** (a line naming the document: invoice,
   form, statement, credit memo or note, receipt, quote, estimate, purchase order, packing slip,
   remittance advice; a stop list in the lexicon), else the first text block that is none of
   those; its address is the 1–5 lines under it until a gap or a label. A page whose only
   candidates are titles yields no vendor. Customer is the block under `Bill To` / `Invoice To` / `Sold To` /
   `Customer`; first line the name, the rest the address. A VAT id, email or phone inside a
   block moves to its own field.
6. Totals (`totals.rs`): candidates for `subTotal`, `totalTax`, `invoiceTotal`, `amountDue`;
   the combination with `subTotal + tax ≈ invoiceTotal` within 1% or 0.01 wins and adds 0.2 to
   each participant (capped 0.99); the largest amount near the bottom labelled total is the
   invoice total when nothing reconciles. Credit: `Credit Memo` / `Credit Note` / `Debit Memo`
   in the top 25% or a negative total sets `CreditNote` and fills `creditSignals`; amounts stay
   absolute, as the service's convention has it.
7. Confidence floor: a field whose confidence is under 0.3 is not emitted (a warning counts
   the withheld fields); `includeCandidates` keeps it visible as a candidate. Document
   confidence: weighted mean over `invoiceId`, `invoiceDate`, `vendorName`, `invoiceTotal`,
   `amountDue` (present fields only) plus the reconciliation bonus; `source` is the tier of the
   pages the fields came from, `Mixed` when they differ, `Spreadsheet` for a workbook.
8. Identifier values (`invoiceId`, `purchaseOrder`, `workOrder`, registrations, serials) are the
   printed token verbatim: the label and any trailing punctuation removed, whitespace collapsed,
   case and inner punctuation kept (`INV-3337`, `E240317201-CN`). The eval already case-folds
   and collapses whitespace; if the consumer's system stores a stripped form, the comparator is
   the place to strip, not the engine.

## 5. Lexicon (English, slice 1)

A reviewed table in `src/core/invoice/lexicon.rs`, seeded from 1037 §3.3 and 2026-11-01 §7.3,
grouped by field, every row **tagged with its language** (`en`, and the `de`, `fr`, `es`
spellings §3.3 recorded: `Rechnung`, `Datum`, `Rechnungsbetrag`, `Facture`, `Montant`,
`TOTAL AVANT TAXES`, `NOTE DE CRÉDIT`, `Factura`, `Importe`). Every row matches regardless of
`InvoiceOptions.languages`; the option orders ties toward its languages and is what a larger
lexicon will gate later. Matching is case- and punctuation-insensitive on a normalised form with
OCR confusables folded (`0/O`, `1/l/I`), scored exact > prefix > fuzzy (one edit per five
chars). The table carries the spellings, not where they were seen. Stop words such as `Terms`
block a date anchor from reading `Net 30` as a date.

## 6. Spreadsheet pages

Nothing special: the projected words carry `cell`, fonts and boxes, so anchors and parties run
as on a PDF. The reimbursement-form fixture pins that `Total` reads the computed amount and that
no vendor is invented when the sheet names none.

## 7. Evidence

- Rust unit tests per module (dates, amounts, identifiers, lexicon scoring, anchor geometry on
  hand-built pages, totals reconciliation).
- ava specs on the two public invoice fixtures (`__test__/fixtures/invoices/*.pdf`) with exact
  values, on three synthetic PDFs written by `examples/gen_fixtures.rs` in the shape of
  clusters A (US, `Invoice No:` / `Total Amount Due`), B (European, `Rechnung`, `31.08.2015`,
  `1.234,56 €`) and C (bilingual `FACTURE / INVOICE`, `Total (CAD)`), one credit memo, and the
  form workbook; type tests for the three additions in both packages.
- Private acceptance: aggregates only (fields found per document, reconciliation rate,
  seconds), and `yarn invoice:eval` once expected files exist. The eval scores the base build by
  default and the OCR build with `PDFDOWN_EVAL_BUILD=ocr`, so the scanned stratum is measured
  with the tier that reads it.
