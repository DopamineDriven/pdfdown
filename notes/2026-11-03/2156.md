Shared code lives in `scripts/lib/` (`corpus.ts` file discovery, `fingerprint.ts` producer/font/header clusters, `expected.ts` the comparable projection of `InvoiceResult`, `metrics.ts`). **Tech Stack:** TypeScript (tsgo for typecheck), tsx, ava 8, pdfdown's `pdfMetadata`, `layoutPerPage`, `attachments`, `extractInvoice`, `extractLayoutWithOcrPerPage`.

**Spec:** `notes/2026-11-03/1037.md` §2 (what the profile reports), §9 (evaluation), §11 step 1, §12 decisions 4 and 5 (defaults: export all ids; promote the profile script). Expected files use `InvoiceFields` names, nothing else: `invoiceId`, `invoiceDate` (`YYYY-MM-DD`), `invoiceTotal`, `amountDue`, `purchaseOrder`, `documentType`, `vendorName`, `customerName`, `shippingAddress.lines`, `items[{productCode, description, quantity, unitPrice, amount}]`, `aircraft[{serialNumber}]`. Whoever produces expected files from another system (the consumer, later) maps into this vocabulary outside this repo.

## Global Constraints

- No value, file name, vendor or page text from the private corpus is printed by default or written anywhere tracked. Scripts print aggregates; a `--verbose` flag may print file names to the terminal only.
- Scripts never commit or modify fixtures; JSON outputs go into the corpus directory, which is gitignored (`report*.json`, `profile.json`, `eval.json`).
- oxfmt / oxlint / tsgo clean; no `as` except `as const`; `satisfies` for literal objects.
- **Every per-document object carries `id`**, the file's basename (a six-digit invoice id in the corpus at hand), so each row traces back to its originating file: `profile.json` entries, `eval.json` entries, both private-corpus reports. Grouping keys are generic: template cluster, text class, producer family. No vendor or business grouping.
- Every task ends with `yarn typecheck && yarn lint && yarn test` green and `git status --short` clean apart from `.vscode/settings.json`.
