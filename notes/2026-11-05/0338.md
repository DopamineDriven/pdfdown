# 2026-11-05 03:38 — Spreadsheet track and the unified PdfDown class: design

A design a builder can plan from. It consolidates `notes/brainstorm/astra-init.md`, `fable-init.md`,
`astra-II.md`, `astra-III.md` and `fable-II.md`, and the spec `notes/2026-11-03/1037.md` §7. Decisions
marked **Andrew** are his; everything marked _call_ is Fable's and can be overridden.

## 1. Intent

Invoices arrive as PDFs and, for one family today and more later, as Excel workbooks. The engine
that reads invoices is template-free and works on positioned text, so a workbook must become the
same `PageLayout` a PDF becomes, and a consumer must be able to open either with one class and
call the same methods. The typed values a workbook already carries are kept as evidence beside
the layout, never as a second extraction path.

## 2. Goals, non-goals, anti-goals

Goals:

- One public class, `PdfDown`, opens a PDF or an `.xlsx` and exposes layout for both, cells for
  workbooks, and later invoice extraction for both. **Andrew.**
- Opening can run off the JavaScript thread (`openAsync`); every expensive method has an async
  form, as today. **Andrew** (ergonomics per Astra-II).
- Structured cells are public from the first release, as their own result. **Andrew.**
- A logical page per selected sheet, with correct display text and label-to-value associations;
  printed-page parity is a later milestone. **Andrew.**
- Pure Rust, WASI-safe, in the base package; the OCR package shares it.
- Aggregates-only evidence from the private corpus; synthetic public fixtures carry the
  expectations.

Non-goals for this release: formula evaluation; printed pagination; drawings and images in
workbooks; rich-text runs; Strict OOXML; macro-enabled and template workbooks; `.xls` and `.csv`;
encrypted containers; locale-dependent formatting beyond the documented fallback.

Anti-goals, what would make this a failure even if it works: a second extraction path keyed on
cells; a value on `TextWord` whose meaning differs by source; display text rewritten into US
conventions against the format code; a workbook that silently loses hidden values, formula caches
or out-of-area cells; a corpus value in any tracked file.

## 3. Constraints

- Branch `dev`, in place; no worktrees. Formatting and type-test rules as in every plan: oxfmt,
  cargo fmt, taplo, no `as` except `as const`, type tests as bare `true satisfies`.
- Dependencies: `zip` with `deflate-flate2-zlib-rs` only (_call_: drop the `deflate` alias that
  pulls zopfli; verify native and WASI), `roxmltree` already present. No tokio, no async zip.
- Every new napi export appears in both packages' typings, the type tests, and the regenerated
  WASI loaders.
- `TextSource` gains `"Spreadsheet"` and `PageLayout` gains optional `sheet` (decision 12.2,
  taken). `InvoiceSource` gains `"Spreadsheet"` when extraction lands.

## 4. The class

Internally one parsed document behind an `Arc`:

```
enum ParsedDocument { Pdf(PdfState), Workbook(WorkbookState) }
pub struct PdfDown { inner: Arc<ParsedDocument> }
```

- `new PdfDown(buffer)` detects the format and parses synchronously, as today for PDFs.
- `PdfDown.openAsync(buffer): Promise<PdfDown>` does detection, archive traversal, decompression
  and parsing in an `AsyncTask` and resolves to an instance. The builder validates on a binding
  test that a static async factory resolves to a real class instance; the sketch is not compiled.
- `format: "Pdf" | "Xlsx"` read-only.
- `layout()` / `layoutAsync(options?)` returns `PageLayout[]` for both formats.
- `spreadsheetCells()` / `spreadsheetCellsAsync(options?)` returns `SheetCells[]`; on a PDF it
  throws an unsupported-operation error.
- Existing PDF-only methods (`metadata`, `document`, `attachments`, forms, text, images, OCR
  variants) keep their types and throw the unsupported-operation error on a workbook. Empty arrays
  keep meaning "supported, found nothing".
- `invoice()` / `invoiceAsync()` on a workbook returns `InvoiceResult` with `source: "None"` and a
  warning until the shared engine exists (_call_; the same shape a PDF without embedded XML returns).
- Standalone `layoutFromXlsx`, `spreadsheetCells`, their async twins, and `detectFormat` are thin
  wrappers over the same internals.
- Errors: napi errors whose message starts with `unsupported format:`, `unsupported operation:`
  or `limit exceeded:` followed by the detail (_call_).
- Workbook state is owned data (no borrowed XML, no shared zip cursor), `Send + Sync` asserted
  like the PDF state. Parsing happens once per instance; layout is computed per call and not
  cached in this release.

## 5. Format detection

`detectFormat(buffer) -> { format: "Pdf" | "Xlsx" | "Unknown", detail?: string }`:

- `%PDF-` header → Pdf.
- Zip magic → read `_rels/.rels`, follow the officeDocument relationship, look the target up in
  `[Content_Types].xml`. The transitional workbook main part content type → Xlsx. Macro-enabled
  or template workbook types, Word and PowerPoint packages, Strict workbooks (root namespace), any
  other zip → Unknown with a detail naming what it is.
- OLE signature → Unknown, "OLE container (legacy .xls or an encrypted Office file)".
- Anything else → Unknown. `openAsync` and the constructor fail with the same detail.

## 6. The workbook model (internal) and the public cells

Parts read through relationships, never by conventional name: workbook, workbook rels, shared
strings, styles, each selected worksheet. Transitional namespaces only in this release.

Internal cell record: sheet index and name, row, column, merge anchor and range, style index,
stored spelling, kind, typed value, formula text or shared-group master, cache presence, display
text, the format code used, whether formatting was supported, hidden flags of its row and column.

Public `SheetCells` (one per selected sheet, in workbook order):

- `sheet`, `index`, `hidden`, `dimension` (declared), `printArea?`, `merges: string[]` (A1 ranges),
  `warnings: string[]`, `cells: SheetCell[]`.
- `SheetCell`: `ref` ("B7"), `row`, `col` (0-based), `kind: "text" | "number" | "boolean" | "error"
  | "date" | "blank"`, `text` (display), `raw` (stored spelling), `number?`, `boolean?`,
  `error?`, `date?` (ISO when kind is date), `format?` (code), `formatSupported`, `formula?`
  (expression when stored on this cell), `sharedFormula?` (master ref when this cell follows one),
  `cached` (a result was stored), `merge?` (range this cell anchors), `hidden`. _Call_ on the
  split of the typed value into optional fields: napi has no clean union for it.
- "Non-empty" includes formula cells with an empty-string cache and error cells; a bare styled
  cell is not emitted. Cells in hidden rows or columns are emitted with `hidden: true` unless the
  caller excludes them.

Rules the inspection fixed: cell type before number format; `<xf>` counted on start and empty
events alike; shared-formula followers carry the master and a cache, no expression; an empty
string cache is cached text; a missing `<v>` is `cached: false` and no `text`; serial 60 is
kind `number` with a warning; both date systems.

## 7. Formatting

Display text follows the cell's format code. Supported in this release: General (integers without
a point, otherwise the shortest round trip, capped at 11 significant digits); fixed decimals with
and without grouping (built-ins 1 to 4 and their custom spellings); percent (9, 10); quoted
literals anywhere, such as a unit suffix; currency and accounting codes with a quoted or plain
symbol, padding tokens `_x` and `*x` stripped; negative sections including parentheses and
colour tags; date and time codes built in 14 to 22 and custom codes with y, m, d, h, s and AM/PM,
where `m` after `h` or before `s` means minutes; the text section `@`. The format parser is a
real parser of sections, literals and tokens, not a scan for letters.

Fallback: en-US separators and symbol placement only where the code leaves a choice; the code's
stated order, literals and symbol position always win; `$` is a glyph, not a currency. **Andrew.**
Unsupported codes, including elapsed durations, scientific notation, locale directives and
conditional sections, keep the raw spelling as `text`, set `formatSupported: false`, and count in
the sheet's warnings.

## 8. Projection to PageLayout

- One logical page per selected sheet, numbered across the workbook in sheet order;
  `source: "Spreadsheet"`, `sheet` set, `rotate` and `contentRotation` 0, `images` empty, drawings
  reported in `warnings` when present. **Andrew** (logical first). Manual breaks are metadata only.
- Page range: the print area when it is a single rectangular range, else the extent of non-empty
  content (not the declared dimension, which the sample shows can be bloated). _Call._
- Width in points is the sum of visible column widths converted with the SpreadsheetML formula
  using the Normal style's maximum digit width, Calibri 11 taken as 7 px at 96 dpi; height is the
  sum of visible row heights in points with the sheet default when absent. Hidden rows and columns
  contribute zero extent. Coordinates are y-up from the page's bottom-left, like every page.
- A cell's text extent is estimated from its own font: characters times 0.5 em times the cell's
  font size (_call_; a documented approximation). Horizontal alignment per the style, with General
  meaning left for text and right for numbers as Excel does (_call_), indent as one em per level
  (_call_); vertical alignment per the style, bottom by default. Explicit newlines make fragments;
  `wrapText` wraps at the cell width using the same estimate and the page warns that wraps are
  estimated; unwrapped text overflows the cell and is clipped to the page.
- Words are the fragment split on whitespace, each with a proportional box and the fragment's
  baseline, `fontName`, `fontSize`, `bold`, `italic` from the cell font, `symbolic` false, no
  `confidence`, and `cell` set to the anchor reference. Merged ranges are one rectangle.
- Words then go through the existing line clusterer; the `cell` identity rides through it on the
  internal word, like the font index, and is asserted after clustering.
- Options: `sheets?: string[]` (names, default every visible sheet in order), `hiddenSheets?:
  boolean`, `hiddenCells?: boolean`. With `hiddenCells: false` (the default) hidden rows and
  columns have zero extent and their words are omitted; with `true` they get their real extents
  back, so the page size and every box are a function of the options, and the clusterer sees
  normal boxes. `spreadsheetCells` takes the same option with the opposite default, so hidden
  cells are listed with `hidden: true` unless excluded. _Call_, settled by the builder check.

## 9. Limits and diagnostics

Compressed input at most 64 MB; at most 10,000 entries; each part at most 64 MB decompressed and
all parts at most 256 MB, enforced by reading one byte past the cap and rejecting the overflow; at
most 2,000,000 cells and 200,000 merges; roxmltree node limit set; no external relationships
followed; nested packages rejected. Every omission a reader could care about is a warning string
on the sheet or the page: unsupported formats (count), drawings omitted, hidden content omitted,
estimated wraps, print-area fallback, serial-60 cells, shared-formula followers without caches.

## 10. Evidence

- Synthetic public fixtures written by `examples/gen_fixtures.rs` as OOXML, at least one Deflate
  and one Stored: a reimbursement-form look-alike (labels, a unit-suffixed rate, a cached shared
  formula with numeric, string and empty caches, a two-row merge with a newline, centred and
  indented cells, hidden rows with values, a print area smaller than the dimension, a date column,
  an accounting negative, a padded identifier, both date systems, serials 59 to 61, an `<xf>` with
  children, Calibri Normal with Arial cells). Expected cells, display strings and warnings stated
  explicitly.
- Rust unit tests for the format parser, serial dates, width conversion, references and ranges,
  limits; ava specs in both packages for the class on PDF and workbook (open, format, layout,
  cells, unsupported-operation errors, async twins), type tests for every new type, WASI build.
- Private acceptance, aggregates only: all 17 workbooks open; every value cell resolves; counts of
  supported versus unsupported formats; pages per sheet with finite ordered boxes. PDF twin pairing
  and label-to-value comparison are a separate later note.
- Harness: the profile reports workbook facts (sheets, dimension, merges, formats) alongside PDFs;
  the eval accepts a workbook beside an expected file once extraction exists.

## 12. Settled by the builder check (Fable's calls)

`TextWord.cell` is a new optional public field, additive. Page numbers run contiguously over the
selected sheets. Rich-text shared strings are concatenated; run formatting is the non-goal, not
the text. One maximum-digit-width constant of 7 px, with a warning when the Normal font is not
one that shares it. "Nested packages rejected" means never opened, not refusing the workbook.
Uncached formula cells are emitted with `cached: false` and empty `text`. Cells outside the page
range stay in the cells result and are omitted from the page with a warning. The zip feature
switch to `deflate-flate2-zlib-rs` is confirmed against the pinned crate's manifest.
