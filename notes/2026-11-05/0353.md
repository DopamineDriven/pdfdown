# Spreadsheet Track and Unified PdfDown Class — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** One `PdfDown` class that opens a PDF or an `.xlsx`, synchronously or with `openAsync`, exposes `layout()` for both, `spreadsheetCells()` for workbooks, and rejects PDF-only operations on a workbook with a clear error; workbook cells are read through package relationships, formatted per their format codes, and projected onto `PageLayout` pages the invoice engine can read later.

**Architecture:** `PdfDown` owns `Arc<ParsedDocument>`, an enum of the existing PDF state and an owned `Workbook`. A `core::spreadsheet` module has four files: `package` (bounded zip and relationships, format detection), `workbook` (parts to a sparse cell model with styles and shared formulas), `format` (format-code parser and renderer), `project` (cells to words on a logical page per sheet). Words carry a cell reference through the existing line clusterer; typed values live in the public cells result, never on words.

**Tech Stack:** Rust, napi-rs 3 (`AsyncTask`), `zip` 9.3 with `deflate-flate2-zlib-rs`, `roxmltree` 0.21, lopdf (unchanged), ava 8 + tsgo type tests, `examples/gen_fixtures.rs` for OOXML fixtures.

**Spec:** `notes/2026-11-05/0338.md` (the design; its decisions marked Andrew are binding) and `notes/2026-11-03/1037.md` §7.
